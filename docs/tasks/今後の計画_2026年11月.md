# muscle-analyzer 今後の計画（2026年11月時点）

本計画は2トラックに分離して進める．**トラックA（卒論コア）**は中山研の卒業研究として評価される部分，**トラックB（プロダクト）**は卒論のスコープ外として自分のペースで進める部分．両者を混在させると卒論の核がぼやけるため，明確に分離して管理する．

---

## トラックB：プロダクト（卒論スコープ外）

Unity統合・3Dアバター・視点非依存レンダリングのアイデア．**研究計画書には将来の発展課題として一文のみ記載**し，評価対象には含めない．進めるペースは任意．

### フェーズ1：技術検証（スコープを絞った小実験）
- [ ] MediaPipeのworld_landmarksが実際にどの程度「視点に依存しにくい」か，同一動作を複数アングルから撮影して精度比較する簡易実験
  - 注意：「視点非依存」と言い切らず「視点依存性の低減」として検証する（過大主張を避ける）
  - 完了条件：正面／斜め45度／真横の3アングルで関節角度推定値のばらつきを定量比較したレポート
- [ ] Three.js（React Three Fiber）でMediaPipeの3D landmarksを簡易rigged人型に流し込むプロトタイプ
  - 完了条件：既存の`AvatarViewer3D.tsx`を置き換え，棒人間ではなくメッシュが動く

### フェーズ2：体型アバター生成（任意・優先度低）
- [ ] 4方向写真からの体型パラメータ推定（肩幅・胴長・脚長等）
- [ ] ベースメッシュへのBlendShape適用
- 判断ポイント：ここまでの工数対効果が低ければフェーズ2以降は凍結し，棒人間/シンプルメッシュのままで良しとする

### フェーズ3：Unity統合の検討（要再検討）
- [ ] react-unity-webgl等でのWebGL組み込み可否を技術検証
- [ ] あるいはUnity抜きでThree.jsのみで十分かを先に見極める（Unity導入は工数が重いため，Three.jsで目的を達成できるなら導入しない判断もあり）

### 優先順位の原則
トラックBはトラックAの進捗を圧迫しない範囲でのみ着手する．卒論提出（2028年1月）までにトラックAが完了していない場合，トラックBは一切手を付けない．

## リスク一覧（再掲・優先度順）

| リスク | 内容 | 対応 |
|---|---|---|
| 高 | トラックBがトラックAの時間を圧迫する | 上記「優先順位の原則」を厳守 |
| 中 | EMG文献の数値化作業が想定より時間がかかる | スクワット・デッドリフトの4筋に対象を限定済み |
| 中 | ST-GCN移行で精度が上がらない | 1D-CNN継続という逃げ道を明記済み |
| 低 | Railwayデプロイのサインアップ停止 | 時間経過で解決見込み，急がない |
