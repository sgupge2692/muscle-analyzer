# 面談記録と防衛ポイント（2026年11月12日）

## 面談で伝えた内容（報告者）

1. 骨格推定からのフォーム矯正アプリは既に存在する（Formax・FormLens・@Kintore・グングンスポーツ等）
2. 「単眼動画から筋活動を推定しヒートマップ表示する」自分のようなアプリは存在しない
3. 市販アプリは「使ってみて精度があんまり」であること（体験談）
4. パイプライン: 機械学習で種目分類 → 分類した種目の角度をMediaPipeで計測 → 角度を参考に公表論文の筋収縮と結び付け

## 評価

- 上記1〜4は競合調査（docs/競合調査_2026年11月.md）の裏付けと一致。実装（backend/src/anatomy/muscle_activation.py の文献較正版）の説明も正確
- 1〜4の記録は v16 の計画書と矛盾しない

## 次回面談に備える追撃質問と防衛線

| 想定質問 | 答え |
|---|---|
| SportsReflectorにも筋活動マップがあるのでは？ | 主張はあるが手法・検証が非公開。開発者リポジトリは角度ベースのルール出力を示唆。検証可能な形で公開した例はない |
| Formatomyはどうなのか | 単眼動画から連続値推定を主張するが未出荷（共同研究者募集中）で公表文献なし。手法と検証を公開した上での提供例はない |
| 論文（Muscles in Action，BioHuman）はどうなのか | 実験室sEMG同期・多視点・大規模計算を要し，スマホ1台・リアルタイムは未達。検証はシミュレーションまたは自己収集sEMGで完結。本研究は公表EMG文献を外部基準とする文献較正パイプラインを中核とする |
| 「精度があんまり」の根拠は | 競合は精度を公開していないため検証不能。だからこそ本研究は検証可能な形で精度を公開する（F1 micro≥0.93＋公表EMG文献とのPearson r 有意の2種類を同時に） |
| 角度→筋活動の妥当性は | Marchetti et al. 2016（スクワット膝角度20°/90°/140°），Escamilla et al. 2002（デッドリフト%MVIC）で較正。較正データは検証データと独立に文献から抽出（逆算禁止） |
| VBTアプリ（Metric等）は速度・1RMを既に実装しているのでは | 速度計測単体は前例あり。本研究の差別化はフォーム逸脱レップの推定除外（フォーム妥当性フィルタ）と筋活動推定との統合 |
| Unity/3Dアバターは | 将来の発展（トラックBは着手前）。3Dアバターからの筋推定は筋骨格シミュレーション研究（OpenSim系）の再実装に近く新規性が弱い |

## 伝える際の注意

- 「精度を上げる」とは言わない。競合の精度は非公開で比較不能 → 「検証可能な形で精度を公開する」が正しい言い方
- 「俺のようなものはない」は「手法と検証を公開した上で出荷されている例はない」と言い換えると審査でも守られる
- 突かれやすい競合（SportsReflector・Formatomy・Metric）は自分から先に言う
